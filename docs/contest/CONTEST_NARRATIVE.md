> "구현됨"으로 서술하지 않고 현재 상태 그대로 표기한다. 수치가 실측이 아닌 시나리오 예시인 경우
> "예시" 또는 "가정"으로 명시하고, 보도·통계 인용은 [`TIMELINESS.md`](./TIMELINESS.md)의 실존 확인
> 기사로만 쓴다.
>
> **2026-09-20 갱신 3건**: ① TourAPI 실적재는 끝났다(활성 1,669곳 / 전체 1,688곳, 2026-09-20 실측).
> ② 경주 시설 혼잡은 **추정**이다 — 실측이 없을 때 주차·관광 통계로 계산하고 화면에 '추정'으로 적는다(§5).
> ③ 혼잡 예측 모델은 현재 **활성 모델이 없다**(`GET /predict/model-info` → `fallback_state: degraded_rules`,

## 1. 독창성 5종 (C1)

NextSpot은 "혼잡한 곳을 보여준다"가 아니라 "지금 출발하면 도착했을 때 여유로운 곳을 골라준다"는
한 문장으로 요약되는 재배치 엔진이다. 그 한 문장을 구성하는 다섯 가지 독창 요소는 아래와 같다.

### ① 도착시점 예측 (현재 혼잡이 아니라 '내가 도착할 시각'의 혼잡을 예측)

경쟁 서비스 다수는 "지금" 혼잡도를 보여주는 데 그친다. NextSpot의 SPOT 산식은 사용자의 이동 시간을
먼저 계산한 뒤, `현재시각 + 이동시간`으로 산출한 **도착 예상 시점**의 `hour`·`dow`를 예측 모델에 넣어
그 시점의 혼잡도를 추론한다. 대기시간(w2)도 동일한 도착시점 기준으로 계산해, "예측은 미래 시점인데
대기시간은 현재 시점"이라는 시점 불일치를 제거했다.

> 근거: `apps/api/app/services/spot/score.py` `calculate_spot_score` — 출발시각(`depart_time`, 없으면 현재) + 이동시간으로 `arrival_dt`를 만들고, `predict_congestion_detailed(type, arrival)`로 도착시점 혼잡을 추론하며(실측 근거가 있으면 모델을 건너뜀), 대기시간도 도착시각(KST)의 시간대로 계산한다.
>
> 단, **지금은 승격된 모델이 없다**(2026-09-20 `degraded_rules`). 도착시점 기준으로 계산하는 구조는
> 코드에 있고 모델이 승격되는 즉시 켜지지만, 발표에서 "지금 예측이 돌고 있다"고 말하지 않는다.
> 현재 순위는 취향(w1)·도착시각 기준 이동·대기시간(w2)·인센티브(w3 쿠폰 항)로 만들어진다.

### ② w3 결합형 인센티브 (개인 효용 + 공익 재배치 기여 + 소상공인 제휴를 한 산식에)

SPOT 스코어는 `w1·선호유사도 − w2·시간비용 + w3·인센티브`로 구성된다. 이 중 w3(인센티브) 항은 서로
다른 두 이해관계자의 이익을 하나의 연속값으로 결합한 것이 독창점이다.

- **쿠폰강도**: 제휴 소상공인의 할인율(`coupon_rate`)을 20% 캡으로 정규화한 연속값 — 소상공인 이익.
- **재배치기여**: `원본 혼잡도 − 후보의 도착시점 예측 혼잡도`(0~1) — 사용자를 혼잡지에서 여유지로
  옮길수록 커지는 값으로, 개인 추천이면서 동시에 B2G 관점의 수요 분산 지표가 된다 — 공익.

두 성분을 `INCENTIVE_COUPON_SHARE=0.5`로 절반씩 결합해 "개인이 받는 혜택"과 "사회가 얻는 분산 효과"를
분리된 지표가 아니라 추천 순위 자체에 내재화했다.

> 근거: `apps/api/app/services/spot/score.py` (`incentive = INCENTIVE_COUPON_SHARE * coupon_term + (1 - INCENTIVE_COUPON_SHARE) * relief_value` — 도착시점 예측이 없으면 쿠폰 항만), 컬럼 정의: `supabase/migrations/20260707150000_add_coupon_incentive.sql`

### ③ 음성 AI 비서

지도를 손으로 조작하기 어려운 도보 관광 맥락을 고려해, 발화 한 턴을 의도(수락/다음/거절/상세/선호필터/중지)로
분류하고 한국어 응답을 생성하는 음성 인터페이스를 백엔드 엔드포인트로 제공한다. "고깃집" 같은 모호한
발화는 백엔드가 구체 검색어로 확장한 뒤 후보 이름·종류 태그의 부분문자열 매칭(`embedding_service.filter_candidates` —
임베딩·벡터검색 없음)으로 후보를 재필터링해, 다른 업종 후보가 섞여 나오는 것을 막는다.

> 근거: `apps/api/app/routers/recommendations.py` (`POST /api/v1/voice/turn`), 프런트 공용 훅 `apps/web/lib/voice/useVoiceAssistant.ts`

### ④ B2G 관제 → 개입 폐루프 (쿠폰 정책이 실시간으로 추천 순위에 반영)

지자체/관광공사 운영자는 관리자 API로 특정 시설의 제휴 할인율(`coupon_rate`)을 즉시 변경할 수 있고,
그 변경은 캐시나 재학습 없이 **다음 추천 요청부터 바로** w3 쿠폰강도 계산에 반영된다. 즉 "정책 개입 →
추천 결과 변화"가 배치 주기 없이 닫힌 루프로 동작한다. 그 개입의 효과는 `/admin/impact`가 수락된
추천의 `원본 예상대기 − 대안 예상대기` 합산으로 정량 집계해 되돌려준다.

> 근거: 정책 개입 `apps/api/app/routers/admin.py`(`FacilityUpdate.coupon_rate` PATCH, 주석: 변경 즉시 다음 추천 요청의 w3 쿠폰강도 `min(1, rate/0.20)`에 반영) · 효과 측정 `apps/api/app/routers/admin.py`(`GET /api/v1/admin/impact`)

### ⑤ 피드백 학습 선호 벡터

사용자가 추천을 수락하면 8차원 선호 벡터가 시설 벡터 방향으로 +10%(추천당 1회) 이동하고, 거절은 `나의 실험실`에서
사유를 확인한 뒤 1회 −5% 이동하며 갱신된다. 다음 추천 요청부터는 갱신된 벡터가 코사인 유사도(w1)에 즉시 반영되어, 별도의
오프라인 재학습 배치 없이 개인화가 누적된다.

> 근거: `apps/api/app/services/preference_vector_service.py` (`adjust_user_vector_on_feedback`), 호출부 `apps/api/app/routers/recommendations.py` (`POST /api/v1/feedback`)

## 3. 페르소나 여정 (C3)

> 아래 시나리오의 인원 수·대기시간·소요시간은 PT 데모 설명을 위한 **예시**이며 실측값이 아니다.
> 각 단계는 실제 앱의 화면 흐름과 호출되는 API를 그대로 따른다.

**페르소나**: 가족 관광객 3인, 첨성대 인근에서 도보 여행 중.

| 단계 | 화면/행동 | 실제 구현 |
|---|---|---|
| 1. 지도 확인 | 메인 지도(`app/main`)에서 첨성대 마커 확인 | Kakao Maps 지도에 시설 마커, 혼잡도별 색상(혼잡=빨강 · 보통=주황 · 여유=에메랄드 · 한산=파랑, 임계 0.75/0.5/0.25) 표시 |
| 2. 혼잡 확인 | 마커 탭 → 혼잡 배지(혼잡/보통/여유/한산)와 근거 출처 표시 | `congestion_logs` 최신 실측 행 기반. 실측·예측이 없으면 **'추정' 배지**(주차 10분 실측 + 관광 집중률, 근거 한 줄 동반)로 내려가고, 그것도 없으면 "데이터 없음". 합성값은 만들지 않는다. **지도 마커에는 추정을 칠하지 않는다** — 추정은 시설 상세·추천 카드·코스 화면에만 붙는다 |
| 3. 대안 추천 | 메인 지도에 SPOT Top 3 카드가 인라인으로 뜨고, 대기 보드(`/waiting`)에서 `/explore/recommend`로 이어진다 | `POST /api/v1/recommendations` — 도보 상한(기본 10분≈1km) 안의 후보에 SPOT 스코어(도착시점 예측 포함) 산정, 쿠폰 있는 한적한 곳이 상위 랭크될 수 있음(w3) |
| 4. 수락 (예시: 3분 내) | 추천 카드에서 "수락" 탭 또는 음성으로 "여기로 가자" | `handleAccept` → `POST /api/v1/feedback`(`action=accepted_visit_intent`) → `recommendations.accepted=true` 갱신 + 선호 벡터 학습 |
| 5. 길안내 | 수락 즉시 카카오맵으로 경로 오픈 | `map.kakao.com` 링크(도보 `/link/map`, 차량 `/link/to`)를 새 창으로 연다(`apps/web/lib/navigation.ts`) |
| 6. 학습 반영 | 다음 추천부터 벡터 반영 | 수락한 시설 벡터 방향으로 선호 벡터가 이동해, 이후 추천의 w1(선호유사도) 계산에 즉시 반영 |

이 여정에서 "쿠폰 있는 한적한 곳"이 우선 노출되는 이유는 임의 배치가 아니라 §1-②의 w3 산식 —
할인율이 높을수록, 그리고 도착시점 기준으로 더 여유로워질수록 점수가 올라가는 구조 — 때문이다.

## 4. 수익모델 (D6)

**B2G 라이선스 (관제 대시보드)**
지자체·관광공사에 관제 대시보드(`/admin/*`, Supabase 로그인 + `users.role` 판정 `require_role(ROLE_ADMIN)`)를 SaaS 라이선스로
제공한다. 시설 CRUD, 쿠폰 정책 개입, 수락률·DAU 지표(`/admin/metrics`), 분산 효과 집계
(`/admin/impact`)가 이미 코드로 구현된 별도 관리자 API 표면이므로 별 도메인 라이선스 판매로
포장하기에 추가 개발 부담이 적다.

**소상공인 제휴 티어 (coupon_rate 연속값 상생 구조)**
`facilities.coupon_rate`는 0/1이 아닌 연속값이며, 할인율이 높을수록 w3 쿠폰강도가 커져 추천 노출
순위가 올라간다(`score.py`). 이는 "제휴 등급이 높을수록 더 많이 노출된다"는 광고 상품 구조가 이미
산식에 내장돼 있다는 뜻이며, 이 등급을 유료 제휴 티어(예: 기본/실버/골드 할인율 구간)로 상품화할 수
있다.

**데이터 리포트 판매**
`/admin/metrics`·`/admin/impact`는 실제 `recommendations`/`user_feedback` 테이블을 집계해 수락률·
재배치 건수·절감 대기시간을 산출한다. 현재는 대시보드 열람용으로만 제공되지만, 동일 집계를 주기적
리포트(PDF/API)로 지자체·상권에 판매하는 것은 별도 판매 기능 개발 없이 집계 로직을 재사용해 확장
가능한 방향이다. (판매 기능 자체는 아직 코드에 없음 — 확장 여지로 서술)

## 5. 데이터 출처와 한계 — 발표에서 먼저 말할 것 (2026-09-20 추가)

심사위원이 묻기 전에 우리가 먼저 말한다. 상세 근거는 [`DATA_UTILIZATION.md`](./DATA_UTILIZATION.md)
§7·§8, 질의응답은 [`JUDGE_QA.md`](./JUDGE_QA.md) Q11~Q14.

| 데이터 | 출처 | 서비스에서 하는 일 | 한계 |
|---|---|---|---|
| POI·상세·축제 | 한국관광공사 TourAPI 4.0(KorService2) | `facilities` 적재 → SPOT w1/w2 입력(§1) | 배치 적재(매일 04:00 KST)라 실시간이 아니다 — `GET /freshness`로 마지막 동기화 시각을 공개한다 |
| 공영주차 실시간 | 경주시 ITS | 주변 권역 수요 + **추정 모드의 주차 성분** | 사람 수가 아니라 근처 차량 수요다. 반경 2km 안에 실시간 주차장이 있는 시설에만 값이 생긴다(활성 1,669곳 중 846곳, 2026-09-20 실측) |
| 실시간 도시데이터 | 서울특별시(서울 열린데이터광장) · **공공누리 제1유형** | 추정 엔진 **검증**(`/admin/engine-validation`)과 권역 분산 **시연** | 경주 서비스 콘텐츠가 아니다. 자기 테이블(`seoul_citydata_snapshots`)에만 쌓고 경주 혼잡 데이터와 섞지 않는다 |

- **경주 시설 혼잡은 추정이다.** `0.7 · 주차 점유율 + 0.3 · 관광 집중률`을 읽을 때 계산하고,
  화면에는 항상 '추정' 라벨과 근거(주차장 수·관측 시각·반경)를 붙인다. `congestion_logs`에 적재하지
  않으므로 모델 학습에도 들어가지 않는다.
- **주차는 임시 방편이다.** 시설 단위 유동인구는 통신사 상용 데이터라 지금 살 수 없다. 서울시가
  같은 성격의 데이터를 무료 공개하고 있어 검증용 정답으로 빌려 쓰고 있고, 경주에도 같은 데이터가
  열리면 입력만 바꿔 끼운다.
- **검증은 숨기지 않는다.** `/admin/engine-validation`은 등급 일치율·인접 등급 일치율·위험 오분류율·
  순위 상관·30분 전망 오차를 기준과 함께 보여 주고, 기준 미달이면 `fail`로, 표본이 모자라면
  `insufficient`로 적는다.
