# AI 운영 플레이북 — Claude Code

AI 코딩 도구를 이 저장소에서 어떻게 쓰는가. 프로젝트 자체의 규칙(게이트·가드레일·파일 위치)은 루트 `AGENTS.md`가 정본이며,
이 문서는 "도구를 어떻게 돌리는가"만 다룬다.

> **2026-09-04 정리.** git 이력으로 확인한 실제 사용: 모든 AI 공동 작성 커밋(2026-06 ~ 09, 290여 건)의 트레일러는 Claude
> (Opus 4.8 → Fable 5 → Opus 5 → Fable 5.1)뿐이다. Codex CLI는 2026-07 PM의 교차 감사에 쓰였고 마지막 흔적은 2026-07-18,
> Gemini CLI는 2026-07-17 검토 래퍼를 만든 뒤 실사용 기록이 없으며, Antigravity IDE는 사용 기록이 없다.
> 그래서 이 문서는 **Claude Code 단일 도구**를 기준으로 쓴다. 다른 도구는 맨 아래 "선택" 절.

## 1. 지침 파일 규약 — 정본 1개 원칙

| 파일 | 역할 | 읽는 도구 |
|---|---|---|
| `AGENTS.md` (루트) | **정본.** 규칙 변경은 항상 여기에만 | Claude Code(`CLAUDE.md` 임포트 경유), Codex 등 AGENTS 규약 도구 |
| `apps/web/AGENTS.md` | 웹 하위 정본(웹 전용 컨벤션) | 위와 동일 |
| `CLAUDE.md`, `apps/web/CLAUDE.md` | `@AGENTS.md` 임포트 포인터 | Claude Code |
| `.agents/rules/nextspot.md` | 워크스페이스 규칙 포인터 | Antigravity IDE로 열 때만 의미 |
| `docs/AI_OPS.md` | 이 문서 | 사람 + 필요 시 에이전트 |

포인터 파일에는 **내용을 직접 쓰지 않는다.** 도구가 자동 로드하는 경로가 달라 포인터가 여럿일 뿐, 실체는 `AGENTS.md` 하나다.

## 2. Claude Code 안에서 역할을 나누는 법

도구가 하나여도 **"지은 쪽이 자기 코드를 검토하지 않는다"**는 원칙은 유지한다. 방법은 세 가지.

| 방법 | 언제 | 어떻게 |
|---|---|---|
| **레드팀 하위 에이전트** | 큰 정리·감사·설계 전, 그리고 실행 후 재검토 | 렌즈가 다른 에이전트 4~6개를 병렬로 띄운다(처음 보는 세션·깨지는 것·문서 정확성·다중 협업·코드 구조·놓친 구석). 계획을 먼저 두드리고, 실행 뒤 다시 띄워 문제가 안 나올 때까지 반복. 2026-09-04 저장소 정리에서 원안 오류 3건을 잡았다 |
| **`/code-review`** | 커밋 전 변경분 검토 | 구현한 세션이 아니라 새 세션(또는 하위 에이전트)에서 돌린다. 발견은 적대적 재검증 후에만 수정(반증 전례: 127.0.0.1 CORS) |
| **읽기 전용 조사 오프로드** | "X가 어디서 쓰이나" 같은 많이 읽고 조금 답하는 조사 | Explore/general-purpose 하위 에이전트에 맡기고 결론만 받는다. 원문이 곧 근거인 작업(설계 입력·보안 조사·불변식 확인)은 넘기지 않는다 |

- **디버깅은 증상·범위·재현 조건을 먼저 정리**하고 하위 에이전트나 새 세션에 넘긴다. 한 세션이 가설·실험 루프를 오래 도는 것은
  컨텍스트 낭비다(전례: `/waiting` 조사에서 이미 해소된 401 유령을 좇아 토큰을 태웠다).
- 하위 에이전트는 **커밋만**, 푸시는 메인 세션이. 같은 워킹 트리를 두 에이전트가 동시에 편집하지 않는다 — 동시 작업은 `git worktree`.
- i18n(4로케일 교차절단 문자열)은 병렬 배정 금지 — 한 에이전트가 단일 소유.

## 3. 표준 루프

1. **설계** — 계획은 대화에만 남기지 말고 `docs/HANDOVER.md` 세션 항목으로(150줄 넘으면 `docs/<TOPIC>_PLAN.md`).
2. **구현** — 본인 브랜치에서. 병렬 작업은 worktree 격리 + 파일 소유권 분할.
3. **게이트 ① 결정적 검증** — `AGENTS.md` 검증 게이트(web / api / 스키마 파리티 / 문서). 실패 시 커밋 금지.
4. **게이트 ② 교차 검토** — §2의 세 방법 중 하나. 구현한 세션 자신의 "다 됐다"를 믿지 않는다.
5. **게이트 ③ 브라우저 검증** (UI 변경 시) — CI의 Playwright e2e(Chromium 390px · 4로케일)가 자동으로 돌고,
   데모 플로우(`docs/contest/DEMO_SCENARIO.md` 체크리스트)는 사람이 `localhost:3000` 또는 Vercel 프리뷰에서 실클릭한다.
6. **머지** — `git push origin <내-브랜치>:main`(fast-forward). main push가 곧 Vercel·Render 배포다.

빠른 버그픽스는 ③을 생략할 수 있지만 ①·②는 생략하지 않는다.

## 4. 세션 간 핸드오프

- 세션들은 서로의 대화를 공유하지 않는다 — 세션 간 컨텍스트 전달 채널은 `docs/HANDOVER.md`가 **유일**하다.
  세션 끝에 "최근 세션" 항목을 남긴다(템플릿은 HANDOVER 하단). 2026-08-28 ~ 09-03의 73커밋이 기록 없이 올라가
  다음 세션이 상태를 git log로 복원해야 했다 — 그 비용이 이 규칙의 이유다.
- 외부 계정이 필요한 작업(Supabase SQL Editor, Render/Vercel env, Kakao·Google 콘솔, GitHub Secrets)은 코드로 우회하지 말고
  HANDOVER "사람 작업 대기"에 기록한다.
- 커밋 작성자는 **사람 본인의 git identity**로 남긴다(GitHub 기여로 잡히게). AI는 `Co-Authored-By` 트레일러로 표기한다.

## 5. 자율(무인) 세션

1. 시작 시 `git log --oneline -25`로 마지막 진행을 확인한다. 워킹 트리가 지저분하면 검증 후 커밋하거나 안전하게 복원한다.
2. **무엇을 할지는 `docs/HANDOVER.md`가 정본** — 과거 로그의 "미완 항목"을 그대로 이어받으면 끝난 일을 다시 잡는다.
3. 병렬 에이전트는 worktree 격리 + 최신 tip 기준으로 시작(stale base 방지), 커밋만 하고 푸시는 통합자가 한다.
4. 각 변경은 게이트 ①을 통과한 것만 커밋하고 즉시 푸시해 유실을 막는다.
5. 파괴적 작업 금지(실 DB 쓰기, 원격 브랜치 삭제, force push). 감사성 발견은 적대적 재검증을 통과한 것만 수정하고,
   반려 항목도 HANDOVER에 기록한다. freeze 백로그 항목은 임의로 착수하지 않는다.

## 6. 컨텍스트 아끼기

Claude 세션의 병목은 컨텍스트와 사용량 한도다.

- **많이 읽고 조금 답하는 조사는 하위 에이전트로.** 파일 읽기는 에이전트 컨텍스트에서 일어나고 메인 세션에는 결론만 들어온다.
  단, 돌아온 답을 file:line으로 되짚을 수 있는 조사에만 — 요약이 핵심을 떨구는 작업(설계 입력·보안 조사)은 직접 읽는다.
- **출력이 큰 명령은 파일로 받아 필요한 부분만 읽는다.** 테스트·빌드 로그는 `tail`, 긴 조사는 스크래치 파일.
- **긴 세션은 HANDOVER 항목을 먼저 쓰고 끝낸다.** 컨텍스트가 요약되기 전에 상태를 문서에 내려놓는다.

## 7. 선택: 다른 도구를 쓸 때

- **Codex CLI** — AGENTS.md 규약을 그대로 읽으므로 추가 설정 없이 교차 검토에 쓸 수 있다. `codex exec -o <새파일> "<지시>"`로
  최종 답만 파일로 받고 종료코드를 확인한다(고정 파일명 재사용 금지 — 실패 시 직전 결과를 새 결과로 오인). Codex는 자체
  샌드박스에서 돌아 환경 의존적 발견(파이썬 버전·네트워크)은 실환경에서 재현 확인 후에만 수용. 파일 수정을 맡기면 §2의
  "같은 워킹 트리 동시 편집 금지"에 걸리므로 직렬 실행 또는 별도 worktree.
- **Gemini CLI · Antigravity IDE** — 운영에서 제외(2026-09-04). 다시 도입하면 이 문서 §1 표와 `AGENTS.md` "AI 도구"에 먼저 적는다.
