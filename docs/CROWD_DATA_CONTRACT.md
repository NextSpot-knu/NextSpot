# 경주 유동인구 데이터 요구 명세 — 통신사 견적·계약용

> 상태: **견적 요청용 초안(2026-10-31)**. 바탕은 [`SEOUL_TESTBED_PLAN.md`](./SEOUL_TESTBED_PLAN.md) §5(계약 명세 초안)와 §7 A6(50m 격자 목표)이다.
> 이 문서는 공급사에 그대로 보낼 수 있게 썼다. 1~10절은 공급사에 보낼 요구 사항이고, 11~12절은 우리 쪽 전환 절차다.
> **"견적에서 확인"** 으로 적은 칸은 공개 자료로 확인하지 못한 값이다. 가격·상품 사양은 지어내지 않았다.

## 1. 무엇을 사려는가

- **용도**: 경주 황리단길 일대의 관광객 분산 서비스 NextSpot. 관광객 앱이 "지금, 그리고 도착할 무렵 덜 붐비는 곳"을 추천하고, 상인·지자체 화면에 혼잡 현황과 분산 효과를 보여 준다.
- **필요한 것**: 작은 격자 칸마다 **지금 그 칸에 머무는 사람 수 추정치**를 10분 단위로, 늦어도 15분 안에 받는 것.
- **쓰는 방식**: 칸별 인원을 그대로 화면에 띄우지 않는다. 같은 칸·같은 요일·같은 시간대의 평소 분포와 견주어 **단계**(여유·보통·약간 붐빔·붐빔)로 바꿔 쓴다. 그래서 절대 정확도보다 **칸 사이·시간 사이의 일관성**이 더 중요하다.

## 2. 요구 사항 요약

| 항목 | 필수 | 있으면 좋음 | 확인할 것 |
|---|---|---|---|
| 공간 해상도 | 격자 한 변 **250m 이하** | **50m 격자**(목표) | 제공 가능한 칸 크기별 가격 — 견적에서 확인 |
| 범위 | 황리단길 기준점 반경 **2km** 안의 전 격자 | 경주 시내 주요 관광지(불국사·보문단지 등) 추가 | 범위별 가격 — 견적에서 확인 |
| 집계 단위 | **10분** | 5분 | 실제 갱신 주기 — 견적에서 확인 |
| 지연 | 집계 끝 → 우리 수신 **15분 이하** | 5분 이하 | 실제 지연 — 견적에서 확인 |
| 지표 | 체류 인구 추정치 | 내국인·외국인 구분 | 추정 방법 설명 |
| 품질 | 신뢰구간 **또는** 표본 플래그 | 둘 다 | 플래그 기준 |
| 개인정보 | 최소 인원 마스킹 + 그 기준값(k) 공개 | | k 값 — 견적에서 확인 |
| 예측 | 없음(자체 예측 가능) | 1~3시간 예측 | 예측 방법·오차 |
| 이력 | 계약 시작 전 **8주 이상** 백필 | 1년(계절·축제) | 이력 기간별 가격 — 견적에서 확인 |

| 라이선스 | 상업 앱 화면 표시 · 파생 지표 · 지자체 보고서 | 계약 종료 후 파생 지표 보관 | 범위·기간 — 견적에서 확인 |

## 3. 공간 해상도와 범위

- **목표 50m 격자, 최대 250m 격자.** 황리단길은 골목 하나 차이로 붐빔이 갈린다. 칸이 크면 같은 칸 안의 가게들이 같은 값을 받아 추천이 후보를 구별하지 못한다.
- 칸이 작을수록 칸마다 추정 오차가 커진다는 점은 알고 있다. 우리는 50~100m 칸 몇 개를 묶은 구역으로도 판단한다. 그래서 **작은 칸 + 칸별 품질 표시**를 큰 칸보다 선호한다.
- **범위**: 황리단길 기준점(위도 35.8361, 경도 129.2105, WGS84) 반경 2km 원과 겹치는 모든 칸. 넓이는 약 12.6km²이고, 칸 수는 대략 다음과 같다.

| 칸 크기 | 칸 하나 넓이 | 반경 2km 안 칸 수(약) |
|---|---|---|
| 50m | 2,500m² | 5,000 |
| 100m | 10,000m² | 1,260 |
| 250m | 62,500m² | 200 |

- **칸 정의를 함께 받는다.** 칸 ID, 중심 좌표 또는 경계 사각형, 좌표계(EPSG 코드)를 준다. 칸 ID는 계약 기간 동안 바뀌지 않아야 한다. 바뀌면 최소 2주 전에 알리고 옛 ID와 새 ID의 대응표를 준다.

## 4. 시간 해상도와 지연

- **10분 집계**, 24시간 매일. 각 행의 시각은 **집계 구간의 시작 시각**이고 시간대를 함께 적는다(예: `2026-10-25T15:00+09:00`). 시간대가 없으면 한국 표준시로 읽는다.
- **지연 15분 이하**: 집계 구간이 끝난 뒤 15분 안에 우리가 받을 수 있어야 한다. 관광객이 5~20분 걸어서 도착할 곳을 고르기 때문이다. 지연이 길면 추천이 과거를 보고 고르게 된다.
- 늦게 고친 값(사후 보정)이 있으면 고친 행을 다시 보내고 그 사실을 표시한다.

## 5. 지표

- **체류 인구 추정치**: 그 칸에 그 10분 동안 머문 사람 수 추정. 통과 인구와 구분되면 둘 다 받는다(어느 쪽인지 정의를 적는다).
- **내국인·외국인 구분**(있으면): 외국인 추정치를 따로 준다. 외국인 관광객 안내와 지자체 보고서에 쓴다.
- **품질 표시**(둘 중 하나는 필수):
  - 신뢰구간(하한·상한), 또는
  - 표본 플래그: `ok`(정상) · `low`(표본 적음) · `masked`(최소 인원 미만이라 가림).
- **최소 인원 마스킹**: k명 미만인 칸은 값을 가리고 `masked` 로 표시한다. **k 값을 알려 준다** — 우리는 가린 칸을 "0 ~ k-1명"으로만 다루고, 값을 지어내지 않는다.
- 단계(붐빔 정도)를 공급사가 따로 준다면 받되, 계산 방법을 함께 알려 준다. 우리는 기본적으로 인원에서 단계를 직접 계산한다.

## 6. 예측(선택)

- 있으면 **1~3시간 뒤** 칸별 예측 인원을 10분~1시간 간격으로 받는다(신뢰구간이 있으면 함께).
- 없어도 된다. 그때는 우리가 이력으로 자체 예측 모델을 만든다(그래서 8주 이력이 필수다).

## 7. 이력

- **계약 시작 전 최소 8주** 이력을 실시간과 같은 형식으로 받는다. 칸별 평소 분포(요일 × 시간대)를 만들고 예측 모델을 학습하는 데 쓴다.
- 가능하면 1년치(봄 축제·가을 성수기·연휴 포함)의 가격도 함께 알려 준다.

## 8. 제공 방식과 형식

- **API(pull)** 또는 **주기 파일**(10분마다 파일 1개) 중 하나. 인증 방식, 호출 한도, 파일 보관 기간을 적는다.
- **가용성 목표(SLA)**: 월 가용성 목표, 장애 통지 방법·시간, 장애 중 빠진 구간의 재전송 여부. 수치는 견적에서 확인.
- **형식 변경**은 최소 4주 전에 알린다.
- **기준 전달 형식** `nextspot.crowd_grid.v1`(공급사 고유 형식이어도 된다 — 우리가 어댑터를 맞춘다. 아래는 받으면 바로 검증할 수 있는 형식이다).

```json
{
  "format": "nextspot.crowd_grid.v1",
  "cell_size_m": 50, "period_seconds": 600, "min_count": 5,
  "cells": [{"cell_id": "G050-0001", "centroid_lat": 35.8361, "centroid_lng": 129.2105,
             "bbox": [129.2102, 35.8359, 129.2108, 35.8363]}],
  "rows": [{"cell_id": "G050-0001", "observed_at": "2026-10-25T15:00+09:00",
            "population": 61.5, "population_low": 48.0, "population_high": 77.0,
            "sample_flag": "ok", "foreign_population": 6.0,
            "forecast": [{"target_at": "2026-10-25T16:00+09:00", "population": 70.0}]}]
}
```

- CSV 로 줄 때는 같은 이름의 열(`cell_id, observed_at, population, population_low, population_high, sample_flag, foreign_population, centroid_lat, centroid_lng`)을 쓴다. 칸 크기·주기·k 는 계약서에 적는다.
- `bbox` 순서는 `[서쪽 경도, 남쪽 위도, 동쪽 경도, 북쪽 위도]` 다.

## 9. 라이선스

다음 사용을 허용받아야 한다. 범위와 기간은 견적에서 확인한다.

- **상업 서비스 화면 표시**: 관광객 앱·상인 화면에 칸·구역별 혼잡 단계와 추정 인원(반올림)을 보여 준다.
- **파생 지표**: 단계, 평소 대비 지수, 예측, 분산 효과 지표를 만들어 저장·표시한다.
- **지자체(B2G) 보고서**: 분산 효과 보고서와 관제 화면에 집계 지표와 그래프를 싣는다.
- **보관**: 계약 기간 중 원자료 보관, 계약 종료 뒤 파생 지표(단계·통계) 보관 허용 여부.
- **출처 표시** 문구와 위치.

## 10. 개인정보와 법

- 받는 것은 **칸 단위 집계 값뿐**이다. 개인 단위 위치, 단말 식별자, 이동 경로는 받지 않는다.
- 공급사가 집계·가명 처리 기준과 최소 인원 마스킹 기준(k)을 문서로 밝힌다.
- 공급사는 그 데이터가 「위치정보의 보호 및 이용 등에 관한 법률」과 「개인정보 보호법」(가명정보 포함)에 맞게 만들어졌고 제3자에게 제공할 수 있다는 근거를 밝힌다.
- 우리 쪽 신고·검토(위치기반서비스사업 신고 필요 여부 등)는 [`PRODUCT_EVALUATION_PLAN.md`](./PRODUCT_EVALUATION_PLAN.md) P3-5 에서 따로 확인한다. 집계 값만 받으면 필요 없다고 보지만 **확인 전**이다.

### 견적 요청 때 함께 묻는 것

1. 칸 크기별(50·100·250m) · 범위별(반경 2km · 경주 시내) 월 가격
2. 실제 갱신 주기와 집계 끝 → 수신 지연(중앙값·최댓값)
3. 체류·통과 인구의 정의와 추정 방법, 내·외국인 구분 가능 여부
4. 신뢰구간 또는 표본 플래그 제공 여부와 기준, 마스킹 k 값
5. 예측 제공 여부·범위·오차
6. 이력 기간별 가격(8주 · 1년)
7. 전달 방식(API·파일), 인증, 호출 한도, SLA 수치, 장애 통지·재전송
8. 라이선스 범위(화면 표시 · 파생 지표 · B2G 보고서 · 종료 후 보관), 출처 표시
9. 계약 전 **샘플 데이터**(반경 2km, 최소 1주, 실제 형식) 제공 가능 여부

## 11. 받은 데이터가 우리 모양으로 바뀌는 방식

통신사 데이터는 어댑터 하나(`apps/api/app/services/crowd/telecom_template.py` 를 복사해 만든다)를 거쳐 엔진이 보는 정규화 관측 `CrowdObservation` 이 된다. 추천 엔진과 화면은 이 모양만 본다.

| 받는 칸 | `CrowdObservation` · `zones` 칸 | 규칙 |
|---|---|---|
| `cell_id` | `zone_id` = `gyeongju:<cell_id>`, `zones.provider_zone_code` | 칸 하나 = 구역 하나(`kind = grid_cell`) |
| `centroid_lat/lng`, `bbox` | `zones.centroid_lat/lng`, `zones.geometry`(GeoJSON), `zones.radius_m` | 반지름 = 칸과 같은 넓이 원의 반지름 |
| `observed_at` | `observed_at` | 집계 구간 시작. 시간대 없으면 KST + `quality.timestamp_assumed_kst` |
| `period_seconds` | `period_seconds` | 없으면 설정값(600) |
| (우리가 받은 시각) | `fetched_at`, `quality.lag_seconds` | 지연이 집계 10분 + 15분을 넘으면 `quality.stale`. 거기서 한 주기(10분) 더 늦으면(35분 초과) 현재값으로 내지 않고 그 구역을 뺀다 |
| `population` | `population_point` | 그대로. 없으면 행을 버린다(0 으로 채우지 않는다) |
| `population_low/high` | `population_min/max` | 내림·올림한 정수. 순서가 틀리면 버리고 `quality.ci_dropped` |
| `sample_flag = masked` + `min_count` | `population_min = 0`, `population_max = k-1`, 점 추정·단계 없음 | `quality.masked` |
| `sample_flag = low` · 넓은 신뢰구간 · 모르는 플래그 | 값은 그대로 | `quality.low_sample` |
| `foreign_population` | `quality.foreign_population` | 엔진이 쓰기 시작하면 칸으로 올린다 |
| (계산) | `level` · `level_label` · `level_scale` | 아래 '단계 계산' |
| `forecast[]` | `forecast[]`(`CrowdForecast`) | 단계는 기준선이 있을 때만. 인원은 구간 또는 폭 0 구간 |

**단계 계산**

1. **기준선 분위수**(`level_scale = telecom_baseline_quantile`): 같은 칸·같은 요일·같은 시간대(기본 1시간)의 과거 인원 분포에서 지금 값이 어디쯤인지(0~1). 표본이 12개(2주 × 시간당 6행) 이상일 때만 쓴다. 가린 행(`masked`)도 "k-1명 이하" 값으로 분포에 넣는다 — 빼면 한산한 시간이 사라져 덜 붐빈다고 잘못 나온다.
2. **보수적 대체**(`level_scale = telecom_density_fallback_4`): 기준선이 모자라면 칸 넓이당 인원으로 4단계를 정하고 구간 중앙값(0.125·0.375·0.625·0.875)을 쓴다. `quality.level_provisional = true` 로 표시한다. 경계는 일부러 낮게 잡았다(덜 붐빈다고 잘못 말하는 쪽이 더 나쁜 오류다).
3. 둘 다 안 되면 단계는 비워 둔다(`quality.level_method = none`).

**수용 시험**(샘플을 받은 날): 샘플을 기준 형식으로 바꿔 어댑터에 넣고, 공급원 계약 테스트(`apps/api/tests/services/test_crowd_provider_contract.py`)에 그 공급원을 한 줄 더해 돌린다. 버린 행 수(`rejected_rows`), 가린 칸 비율, 반경 2km 칸 채움률, 지연 분포를 함께 본다.

## 12. 전환 체크리스트(데이터를 산 뒤)

| # | 단계 | 할 일 | 끝난 기준 |
|---|---|---|---|
| 1 | 구역 적재 | 칸 정의 → `zone_table_rows()` → `zones` 표(`region = gyeongju`, `kind = grid_cell`, `cluster = hwangnidan`). 원격 적용은 사람(SQL Editor) | 반경 2km 안 칸이 빠짐없이 들어감 |
